# Todoist 收集箱任务规范


## 1. 任务归属与上报条件

- 个人事项及确需用户操作、授权、提供信息或决策的异常，进入 Todoist **收集箱 Inbox**；团队执行与协作任务进入 Linear。必要时在 Todoist 只记录用户个人动作并关联 Linear，不复制团队任务。
- 所有新建 Todoist 主任务明确设置 `projectId: "inbox"`；子任务设置 `parentId`，归属 Inbox 主任务。不得使用“工作”“个人”等其他项目或另建项目。
- AI 能独立完成的排查、修复、合并、重试、测试等，不得变成用户待办。先在既有授权范围内处理；可安全自动恢复的临时异常不上报。
- 只在确实存在人工阻塞、需要用户决策，或用户明确要求记录个人待办时写入 Todoist。未确认原因时不得将猜测写成结论。
- 不在任务描述中写“AI 后续安排”“授权后 AI 将……”“后续由 AI……”等计划。AI 自己的工作留在原自动化、Linear 或执行记录中；Todoist 只写用户待办。

## 2. 先查重，后写入

1. 根据**对象 + 问题 + 用户待办动作**搜索现有未完成任务，包含 Inbox 以外的旧任务；重复内容只更新，不新建。
2. 更新现有任务前读取标题、描述、标签、已有子任务和对话链接。保留仍有效的上下文和历史链接；进展仅补充发生变化的事实。
3. 命中 Inbox 外的个人任务时，如可安全迁移则移入 Inbox；迁移可能破坏共享协作关系或父子层级时，不擅自迁移或创建重复任务，直接说明冲突。
4. 同一根因的重复告警合并到同一主任务。只有用户确有另一项独立行动时才创建新任务。

## 3. 标题与描述

- **标题**：以动词开头，说明明确的待办动作和具体对象，≤25 个汉字。不要使用“处理异常”“继续排查”“待确认”一类空泛标题。
- **描述**：普通任务保持 1～3 句。说明**具体对象、已确认的问题、实际影响、必要的操作要点或完成标准**；没有的字段省略，不强制凑齐。
- **推荐字段**：必要时使用“当前情况”“处理要点”；确需用户取舍时使用“待决策事项”。标题已说明动作时，描述不再机械重复标题。
- **措辞**：采用 ASD-STE100 的简洁原则：常见词、短句、具体动作、已证实事实。保持中性，不写“需要你做”“请你处理”“协助事项”“后续安排”等指派式、客套式或无必要标签。
- **事实**：对象具体到项目、文件或功能；问题只写确认事实；影响说清哪个实际动作受阻。尚未尝试合并时只写“修改重叠，尚未合并”，不得写“无法合并”。
- **路径**：使用“项目名 + 相对路径”；必要时附真实链接，不用冗长绝对路径。
- **排除**：不写检查流水账、完整技术报告、原始堆栈、易过期数量、提交 SHA、推测性执行预案或密码/密钥/Token。详细资料用真实链接关联。

### 普通任务示例

- **标题**：`重新授权 Hermes 数据库连接`
- **描述**：`当前情况：Hermes 的 PostgreSQL 只读连接认证失败，日报数据读取暂停。处理要点：在凭据管理系统中重新授权只读连接。`

也可直接写成自然句，不强制添加字段名：

`Hermes 的 PostgreSQL 只读连接认证失败，日报数据读取暂停。重新授权只读连接后，此项待办即完成。`

## 4. 复杂任务：用子任务，不堆描述

- **一步可完成**：只创建主任务，不创建子任务。
- **2～5 个独立人工动作**：创建一个主任务 + Todoist **原生子任务**。子任务标题以动词开头，明确操作对象；必要时在子任务描述补充操作位置、判断标准。
- **跨系统、多阶段、根因尚待确认**：主任务只概述已确认的阻塞，先拆出目前**确实需要用户完成**的操作。未确定的阶段不要预先变成用户待办。关联 Linear Issue、文档或日志以供深入查看。

### 多步示例

**主任务**：`恢复 Hermes 数据库访问权限`

**描述**：`当前情况：数据库只读账号认证失败，日报数据读取暂停。按照子任务完成账号及凭据授权。`

**子任务**（仅在这些操作确需账号持有人执行时创建）：

1. `确认数据库只读账号状态`
2. `更新凭据管理系统中的授权`
3. `确认只读账号具备所需访问权限`

## 5. 决策型待办

已调查且确需用户决定时，以**“待决策事项”**标识取舍。写明选项、影响与建议，确保用户可以直接选择：

```markdown
**待决策事项**：<要决定的具体问题>
**选项 A**：<做法及影响>
**选项 B**：<做法及影响>
**建议**：<推荐选项及一句话依据>
```

只在存在真实取舍时使用，避免重复确认已有授权；不得借“待决策”向用户转交 AI 自己的分析工作。

## 6. 元数据与链接

- **优先级**：`p1` 仅用于紧急或阻塞他人；`p2` 用于本周重要事项；其余默认为 `p4`。不得仅因为发生报错就使用 `p1`。
- **日期**：按用户明确要求设置；未指定不设置截止日期、执行日期或提醒。
- **更新链接**：保留原有对话链接；本轮有新决定、处理结果或有效上下文时追加真实本轮链接，去重。无法取得链接时不要填占位内容，并在反馈中说明。

## 7. 工具执行与回读

1. 查重并读取匹配任务；决定更新还是新建。
2. 新建主任务指定 `projectId: "inbox"`；子任务指定 `parentId`。更新时只传修改字段，迁移前确认不会破坏层级与协作关系。
3. 写后回读主任务及必要子任务，检查 Inbox 归属、标题、描述、子任务层级、标签、优先级、日期及真实对话链接。
5. 部分写入失败、权限不足或回读不一致时明确说明，不得声称全部成功。

## 8. 对用户的反馈

只报告实际写入结果和重要缺失，不生成第二份工作报告。原则上使用：

```markdown
已创建／已更新：[任务标题](真实任务 URL)
位置：Todoist 收集箱
当前情况：<仅在说明阻塞时写一句>
处理要点：<仅在标题不足以说清操作时填写>
```

- 复杂任务可补充“操作清单：3 项”，无需在聊天里全文重复子任务。
- 决策任务用“待决策事项”及具体选项替代“处理要点”。
- 普通个人待办只返回结果和链接即可。
- 不出现“需要你做”“协助事项”“后续安排”“下一步由 AI……”等字段。
- 未取得真实 URL、对话链接或验证失败时，简要告知相应限制。

## 9. 最终输出示例（必须参照）


### 示例 A：单步阻塞，成功创建

**Todoist 主任务**

- 标题：`重新授权 Hermes 数据库连接`
- 项目：`Inbox`；优先级：`p2`；标签：`权限`
- 描述：

```markdown
当前情况：Hermes 的 PostgreSQL 只读连接认证失败，日报数据读取暂停。重新授权该连接后，待办即可完成。

[Hermes 对话](https://example.com/ai/conversations/session-001)
```

**最终回复**

```markdown
已创建：[重新授权 Hermes 数据库连接](https://example.com/todoist/tasks/task-001)
收集箱 · P2 · 权限
当前情况：数据库只读认证失败，日报读取暂停。
任务 URL：https://example.com/todoist/tasks/task-001
AI 对话：https://example.com/ai/conversations/session-001
```

### 示例 B：复杂阻塞，主任务 + 子任务

**Todoist 主任务**

- 标题：`恢复 Hermes 数据库访问权限`
- 项目：`Inbox`；优先级：`p1`（仅在确实紧急或阻塞他人时）；标签：`权限`
- 描述：

```markdown
当前情况：只读账号认证失败，日报数据读取暂停。按子任务完成必要的人工授权操作。
排查记录：https://example.com/issues/issue-002

[Hermes 对话](https://example.com/ai/conversations/session-002)
```

原生子任务：

1. `确认数据库只读账号状态`
2. `更新凭据管理系统中的授权`
3. `确认账号访问权限`

**最终回复**

```markdown
已创建：[恢复 Hermes 数据库访问权限](https://example.com/todoist/tasks/task-002)
收集箱 · P1 · 权限
待处理事项：3 项子任务，已按操作顺序创建。
任务 URL：https://example.com/todoist/tasks/task-002
排查记录：https://example.com/issues/issue-002
AI 对话：https://example.com/ai/conversations/session-002
```

### 示例 C：需要取舍，更新已有任务

**Todoist 主任务**

- 标题：`选择 Skills 同步冲突处理方案`
- 项目：`Inbox`；优先级：`p2`；标签：`决策`
- 描述：

```markdown
当前情况：shadcn 与同步清单的本地修改和线上更新重叠，尚未合并，同步已暂停。

**待决策事项**：选择保留哪些修改。
**选项 A**：保留本地定制，需人工处理重叠部分。
**选项 B**：采用线上版本，本地未同步的定制将不保留。
**建议**：优先保留已确认需要的本地定制，再按实际差异处理重叠内容。

[Codex 对话](https://example.com/ai/conversations/session-old)
[Codex 对话（本轮）](https://example.com/ai/conversations/session-003)
```

**最终回复**

```markdown
已更新：[选择 Skills 同步冲突处理方案](https://example.com/todoist/tasks/task-003)
收集箱 · P2 · 决策
待决策事项：保留本地定制，还是采用线上版本？建议保留确认需要的本地定制。
任务 URL：https://example.com/todoist/tasks/task-003
AI 对话：https://example.com/ai/conversations/session-003
```

如无法获取真实任务 URL，只返回“任务 ID：<实际 ID>（任务 URL 暂不可用）”；如无法取得 AI 对话深度链接，说明“AI 对话链接暂不可用”，并且任务描述中不写虚构链接。更新任务时，真实历史链接仍应保留。

## 自检

确认：**仅 Inbox**；**查重后写入**；**标题是用户的具体行动**；**事实与影响准确**；**复杂事项拆成原生用户子任务**；**没有 AI 后续安排或代理工作转嫁**；**对话链接真实且去重**；**写后回读并返回任务链接或 ID**。不符合则修正后再反馈。
