# Validate

按本次变更选择必要检查，分别记录“静态检查、目标环境、试跑、业务验收”的结果。

1. **静态检查**：运行项目已有 Lint；采用通用描述时运行辅助程序 lint。按字段定位依赖、引用、完成条件和边界错误。核对实际交付文件与 build 中的默认结构或已配置替代项，确认运行入口引用真实文件。
2. **目标环境**：核对执行平台、时区、工作目录、解释器、依赖和所需访问能力。preflight 提供当前环境快照；目标执行器不同则另取其证据。仅在已验证范围内标 passed，其余标 unknown。
3. **试跑**：确认命令实际副作用，选择样本或隔离输出。验证所改步骤及其风险对应的失败路径；已有外部写入先对账再恢复。
4. **业务验收**：依 completion 核对产物内容、数量、新鲜度、格式及必要交付回执，记录结果。

## 按风险选择验证

| 本次涉及 | 应核查 |
|---|---|
| 超时、重试或预算 | 执行器实际终止行为、退避和次数；仅有监控能力的标“监控” |
| 重复运行、并发写入 | 幂等键、资源锁范围、持有者与租约 |
| 断点或缓存 | 输入、配置/脚本版本、已验收产物是否匹配 |
| 采集与降级 | 空输入、数据未就绪、来源不可达或可选步骤失败的出口 |
| 调度接入与版本更新 | 目标调度器的真实入口、工作目录、时区与权限；样本试跑、原版本恢复方式、新旧任务不重叠 |
| 多任务共享资源 | 上游完成与数据窗口、锁的作用域、共享额度、重复触发及错过周期的处理 |
| AI 输出与成本 | 最小输入、结构化结果、异常或超长输出、真实预算控制；无法强制限制则注明 |

修复后复测受影响部分。对新建或变更的调度，分别标记未部署、已部署未观测、已观测；未验证目标执行器时不得宣称上线可用。原因未知时进入 diagnose。

**结束条件**：本次验收项均记录 passed/failed/unknown、检查范围和证据。业务完成条件全部通过时报告完成；其余给出对应失败或缺失证据。
