# Design

1. 核对目标环境的命令、连接器与持久化能力，标出待验证项。以现有执行器和原生配置为基础设计。
2. 按下表分工；将混合步骤拆为采集、判断、校验或执行。
3. 建立任务关系与故障出口，按需采用下列恢复规则。

| 执行主体 | 适用事项 |
|---|---|
| 脚本 | 规则稳定、输入输出明确且运行环境可访问：取数、清洗、去重、校验 |
| Agent 工具 | 数据仅通过目标 Agent 的连接器可达；将结构化结果交给后续步骤 |
| AI | 语义理解、业务解释、未知原因分析；约定所需证据与输出字段 |
| 人 | 尚待决定的业务规则或授权 |

## 任务关系

为每步定义稳定 ID、执行主体、输入输出、成功条件、时间上限和失败出口。用紧前依赖推导紧后任务；写清条件分支的成功、跳过、失败和降级含义。

并行步骤须无数据或资源冲突；共享写入明确串行、事务或锁。外部关联记录真实工作流 ID、输入输出契约与接入状态。涉及多个定时任务时，先核查实际调度清单及共同资源（文件、数据库、API、模型额度）；定义锁/配额作用域、上游数据就绪条件和跨任务冲突处置。不得仅靠相邻 Cron 时间表达依赖。

触发器区分计划时刻、实际启动和业务数据窗口；明确时区、迟到/漏跑补偿、补跑范围与已处理窗口去重。空数据和数据尚未就绪是不同状态。

## 停止与恢复

| 情况 | 设计要求 |
|---|---|
| 等待、重试、成本增长 | 设置有限预算，记录负责落实限制的执行器；未具备的限制标为待实现 |
| 暂时性故障 | 有限重试与退避；权限、配置或规则缺失转 blocked |
| 重跑存在写入或发送 | 业务幂等键与去重/事务；回执未知时先对账 |
| 中断恢复 | 断点绑定输入范围、数据和配置版本、已验收产物；原子提交后推进 |
| 跨轮重叠 | 明确跳过或排队；需要租约时定义持有者、有效期及恢复方式 |
| 连续失败 | 定义停止阈值、通知去重、恢复条件及负责落实的组件 |
| 交付或通知失败 | 区分主任务完成与通知失败；保留交付回执，重试前确认是否已送达 |
| 可选步骤失败 | 定义降级产物；必需步骤决定整体完成状态 |

为 AI 步骤约定最小输入、数据规模上限、结构化输出、可用工具和成本上限；稳定分支由脚本判定。记录版本、数据窗口与运行标识，使历史结果可复现。需要机器检查时按 contract 建立兼容描述，其来源保持可追溯。只为实际缺失的能力增加组件。

**结束条件**：每步均有执行主体、输入输出、完成判据和失败出口；依赖与分支闭合；限制有执行者或明确待实现项。交付摘要与任务关系，已授权实现则进入 build。
