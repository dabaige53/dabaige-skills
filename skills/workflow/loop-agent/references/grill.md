# Grill

1. 从当前请求和项目资料提取已知目标、输入、产物及完成标准。区分已确认事实、用户选择与待核查环境。
2. 选择一个会改变下一步的缺口，每轮问一个问题，附推荐选择和具体例子。让用户决定业务规则；可探测的环境信息交给工具。
3. 将答案补入需求，继续处理仍阻碍设计的缺口。

按当前任务选择问题：

| 缺口 | 需要确定 |
|---|---|
| 目标 | 使用者、要解决的问题、范围 |
| 输入 | 来源、时间窗口、新鲜度、可用样例 |
| 产物与完成 | 内容、目的地、验收条件、空数据及部分成功处理 |
| 触发 | 定时/事件/手动；定时时区、重叠与漏跑策略 |
| 运行条件 | 目标执行环境、连接方式、最长等待和尝试上限 |
| 失败处置 | 数据未到、错过周期、连续失败时是否补跑；通知对象、渠道和人工恢复条件 |

示例：

> 当天没有新增数据时怎样处理？建议记录“无新增”后结束；例如昨天已处理的销售记录，今天直接跳过。

**结束条件**：目标、输入、产物与可检查的完成标准已明确，影响下一步的业务选择已解决。剩余环境事实标为待验证；低影响实现选择作为可见假设。

返回精简需求摘要。用户要求继续构建时进入 design；只要求梳理时在此完成。
