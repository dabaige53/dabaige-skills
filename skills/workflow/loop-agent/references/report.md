# Report

1. 选择工作流与本轮 run，读取配置和对应事件。多轮混在一起时先按 run 分离。
2. 从紧前依赖推导紧后与并行关系；从事件提取实际开始、重试、跳过、失败和结束。配置决定计划关系，事件决定实际轨迹。
3. 采用通用事件时读 contract 并运行 report；否则使用平台已有查询。已有证据足以回答时直接返回。
4. 先给当前状态，再按用户所问选择下列内容。

| 所问内容 | 返回 |
|---|---|
| 运行到了哪里 | 当前步骤、最后进展、状态、受阻紧后任务和恢复条件 |
| 依赖或关联 | 紧前/紧后、分支条件、真实关联工作流及接入状态 |
| Agent 执行信息 | run/step/attempt、实际 Agent 或会话 ID、角色、执行器 |
| 实际路线 | 本轮事件与时间；并行分支分列，片段或跨来源顺序标明范围 |
| 成本 | 实测耗时、Token、工具调用和重试次数，以及统计覆盖范围 |
| 多轮趋势 | 使用 audit 或平台历史查询；列出同因失败签名、超预算、静默和版本差异，注明样本范围 |
| 部署与恢复 | 调度入口版本、最近观测运行、影响范围、恢复动作和未完成交付 |
| 设计或交付 | 简短设计摘要、实际变更文件树、产物与验收结果 |

未采集项写“未知”。统计覆盖不完整时，将已知数值之和标为“已观测合计”，总量保留未知；步骤耗时之和与首末事件跨度分别标注。比较优化效果时使用输入范围、统计口径一致的前后实测值。

**结束条件**：用户所问状态、关系或路线已有对应证据，差异与缺口明确。输出只保留相关行；失败、阻塞或未验证时附所需动作。
