# Skills Check

检查 Skill 的 `SKILL.md`、`references/` 等 Markdown 文件，删除不改变 Agent 行为的内容，并让 Skill 只靠自身内容就能使用。用用户的语言回复。

每个候选只问一个问题：

> 这段内容在什么条件下改变 Agent 的哪个动作？这个作用是否只在这里出现？

答不出具体动作就删除；作用真实但别处已有，保留最清楚的一份。扫描命中只用于定位，结论以这个问题为准。

## 范围

- 用户给了路径：检查这些 Skill 目录或文件。
- 没给路径：检查当前对话正在处理的 Skill；仍不明确时询问。
- 用户只要求审查：按 `处理 | 位置 | 依据` 报告，价值最高、风险最低的排在前面，不改文件。否则直接清理。

## 低价值内容

删除只为以下目的存在的整句或整段，不换成更委婉的说法：

- **重复检查**：后面的句子再次要求前文已经要求的事，例如已写“没有的字段省略”，又写“这些标签并非每条必填”。
- **空洞收尾**：结尾句只复述上文已经说明的内容。
- **无条件告诫**：“注意”“必要时”“尽量”“务必”之类，没有写明条件和动作，照做也不会改变任何行为。确有必要时改写成“在某条件下做某动作”，只保留一处。
- **强制每次输出的章节**：要求每次回复都带限制、风险或免责说明，无论有没有内容可写。改为在存在具体阻塞、失败或未决事项时才写，否则删除。
- **层层例外**：围绕一次失误堆积的“除非”“但”“也不要”。把底层规则重写一次，覆盖这些情况。
- **重复规则**：同一要求出现在多个文件或章节。保留在负责该范围的文件中，删掉其他副本。

以下内容会改变输出，看起来像告诫也要保留：

- 用户选定的输出要求、授权边界、安全限制和必需检查。
- 会改变规则应用方式的原因说明。

## 自包含

Skill 会被安装到不同目录、分发给不同 Agent。其他 Skill 的位置和内容随时可能变化，所以 Skill 不能依赖它们的文件。

- **引用其他 Skill 的内容**：写着“参考/按/取自 X Skill”“该 Skill 的 `domain.md`”，或链接到其他 Skill 目录里的文件。读出被引用内容中真正影响本 Skill 动作的关键信息，提炼后写进本 Skill 对应的位置，然后删掉这条引用。只提炼本 Skill 用得到的部分，不整段搬运命令细节或对方的专属流程。
- **调用其他 Skill 做事**：例如“查相似故障使用 `Search` Skill”。这是把任务交给另一个 Skill，不是引用对方的内容，所以保留，但只写 Skill 名称，不写路径。
- **跨目录链接**：链接目标在本 Skill 目录之外，例如 `../../other/SKILL.md`。属于引用内容的按上一条提炼；属于调用的改为只写名称。
- **写死安装路径**：例如 `~/.claude/skills/...`、`~/.codex/skills/...`。改为相对本 Skill 根目录的路径，或改为只写 Skill 名称。
- **本 Skill 内的链接**：例如 `references/x.md`、`../assets/...`，会随 Skill 一起移动，保留。

## 清理残留

- 坏链接、指向本 Skill 中已不存在文件的路径：修正目标；目标内容已删除时，连同只为它存在的句子一起删除。
- 删除某段内容后，检查有没有规则还在维护、保留或链接这段内容，一并删除。

## 流程

1. 查看仓库状态，保留与本次无关的改动。
2. 扫描目标路径：

   ```bash
   python3 scripts/scan.py <Skill 目录或文件> [--signal NAME] [--max N]
   ```

   脚本位于本 Skill 目录下，只列出候选，不修改文件。信号对应上文各类问题：`cross-skill`、`skill-reference`、`install-path`、`broken-link`、`missing-path`、`duplicate`、`denial`、`vague-caution`、`every-output`、`exception-chain`、`closing-summary`。扫描漏掉的内容同样要判断。
3. 逐个阅读候选及其上下文，按上面的问题判断。认定是重复或无用之前，先查找加载或引用它的所有文件。
4. 直接删除确认无用的内容，不留删除说明、占位章节或新的免责声明。删除前把其中独有的命令、原因或条件移到它该在的位置。跨 Skill 引用按“自包含”一节提炼后再删除。
5. 用户指定了删除粒度就照做；没有指定时，删除只为该目的存在的整个单元（句子、段落、表格行），不要改写成换个说法做同样的事。
6. 重读修改后的文件，修正引用了已删内容的地方。同一问题在范围内反复出现的，全部清理。
7. 对改过的文件再跑一次扫描：`--signal broken-link --signal missing-path --signal cross-skill --signal install-path`。通过即结束，不重复验收。

## 报告

说明改了什么、检查结果，以及存在的阻塞或失败，附文件和行号。不列出没有问题的项。
