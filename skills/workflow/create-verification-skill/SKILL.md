# 创建项目验证 Skill

从仓库里的启动命令、用户入口和已有操作脚本查起。确定要验证哪个应用、怎样识别可用的实例、需要哪些数据，以及什么结果能证明功能可用。项目有多个应用时，根据本次任务选目标。

## 放到项目里

遵循目标项目的 Skill 源码约定。普通 Codex 项目使用 `.agents/skills/verify-<app>/`。如果这个位置由 Magpie 分配，沿链接查到维护目录，在获准的源码位置编写；新增分配使用项目既有的 Magpie 入口。已有对应的验证 Skill 时，使用 `$maintain-verification-skill`。

在目标目录编写 `SKILL.md`。用英文填写实际的 `name`，在 `description` 中写明应用、用户入口和适用任务。沿用项目的调用策略。

## 写出能实际使用的操作步骤

- **启动与检查**。使用项目自己的启动命令、迁移和验证数据，给出一次只读检查，确认构建版本、实例归属和功能就绪。服务或 UI 使用隔离的端口、数据目录或配置。短命令每次单独运行，TUI 使用独立终端会话。共享实例无法隔离时，先确定可安全执行的操作。
- **操作与证据**。优先复用已有脚本，使用真实的命令、路由或可访问性标签。记录用户做了什么、看到了什么，以及对应文件、数据或响应发生了什么变化。使用预览模式时，观察其实际副作用。配套脚本应可执行，并在正文中写出调用方法。
- **清理**。只清理本次创建的进程、会话和临时数据。证据另存于项目指定的位置；本机临时产物使用 `/private/tmp`。清理后确认仍能打开证据。失败的尝试同样清理。

## 建立功能清单并试用

在 `features/README.md` 列出本次覆盖的功能和已有入口。每个功能单独一页，写明子功能、用户从哪里进入、操作步骤与可观察结果，以及数据和权限等前置条件。可参考[完整示例](references/feature-map-example/README.md)。示例里的命令和数据应换成目标项目的实际值。

说明要试哪项功能及原因。在当前授权内，从用户入口走通一个代表功能：启动、检查、操作、保存证据、清理。某个入口未运行时写清原因，替代环境的结果只算该环境。遇到产品故障，记录现象和复现位置；浏览器、桌面、外部写入和全量测试沿用当前项目授权。交付源码位置、已跑通的入口、证据位置及未验证项。后续用 `$maintain-verification-skill` 维护。
