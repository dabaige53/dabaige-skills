# Hermes Handoff

让 Hermes 从可核实的工作状态继续完成用户目标。适用于开发、排错、研究、文档、部署和运维等任务；交接内容和深度随任务变化。

完成交接的标准：Hermes 能知道要完成什么、取得哪些材料、从哪里继续、有哪些约束，以及如何验证结果。生成提示词不等于材料已送达或接收方已执行。

## 1. 确定目标和范围

从当前请求、仍适用的会话确认和目标项目资料中提取：

- 用户期望的最终结果、交付物和验收标准。
- 已确认的范围、优先级、限制及不在本次范围内的事项。
- 本次是仅生成接力提示词、保存交接文件，还是还需执行前置准备或发送交接内容。

明确请求优先于旧方案；保留仍有效的用户决定，不把已放弃的方向重新列为任务。目标不明确时先询问关键目标，不自行扩展为部署或重新开发。

所有项目名称、仓库地址、账号、主机、目录、数据源、端口和运行方式均从本次上下文获取。技能不预设具体值，不将单次交接的环境信息写入通用规则。源环境的路径、身份和工具可用性不能直接视为 Hermes 环境的配置。

## 2. 还原可继续的工作状态

阅读足以确定接手位置的材料，按需要记录以下内容；简单任务可合并，不为无关项创建空章节。

- **当前进度**：已完成、进行中、未开始和受阻工作；进行中的任务说明最后完成的步骤及下一步。
- **关键决策**：已选方案、必要理由、必须保持的行为或约束；仅保留会影响后续工作的备选方案和失败尝试。
- **验证证据**：实际执行的检查、对应版本或输入、结果和证据位置。区分未检查、通过、失败和异步待完成。
- **活动工作**：仍在运行的进程、远程任务或其他协作者，以及它们负责的范围和结果获取方式。源会话中的进程或工具句柄不视为可迁移状态；必要时提供接收方可用的定位信息。
- **未决问题**：每项缺口的影响、解决方法和责任方；区分阻止开始、仅阻止某一步、暂不影响继续工作的事项。

对影响下一步的事实注明来源或核实时间。会话总结只是线索，关键版本和执行结果尽量用当前材料核对。缺失事实标为“未核实”，只有实际检查后确实不存在才写“未发现”。

## 3. 确认材料和环境可达

列出完成任务所必需的材料及获取方式，优先提供接收方可访问的仓库、文件或文档引用。长篇背景留在可访问的附件或文件中，提示词保留目标、约束、接手点及阅读入口。

为每项必要材料区分：源位置、已知的接收方获取方式、版本标识，以及“已确认可访问”“待接收方核实”或“尚未交接”。本机路径只能说明源位置；没有传输或共享证据时不能声称 Hermes 可访问。仅在材料需要时记录目标路径，未知时交由 Hermes 确认。

按任务采用相应检查：

- **代码**：确认实际版本控制方式。使用 Git 时核实 remote、分支、HEAD、未提交及未发布变更；指出接收方可获取的提交与本地状态的差异。对未提交文件说明其影响及已授权的交付方式，不能仅凭仓库链接声称已完整交接。
- **访问权限**：确需远程访问时核实用户指定身份的权限和待接受邀请；身份未知时不使用当前登录账号代替。fork、直接 clone 或其他方式依据协作要求和实际权限选择。
- **运行环境**：核实与任务有关的运行入口、工具及版本要求、配置项名称、检查方式。项目实际使用容器、共享存储等技术时才加入对应步骤；本机安装不证明目标环境已具备。
- **研究或文档**：提供原始需求、来源、草稿及版本、已核实结论和引用缺口；使 Hermes 能区分事实、推断与尚待验证的内容。
- **数据与产物**：明确必要输入的格式或版本、获取方式、读写边界及产物保存要求。源数据与运行产物分别处理；数据复制和写入策略依据任务用途与已有授权确定。

凭据通过目标环境的安全配置方式提供。交接文本记录配置项名称和获取方式，不包含密钥值或无关业务数据。

## 4. 完成已授权的前置准备

依据当前请求和仍适用的授权执行前置操作，目标、操作和影响不变时沿用已有授权。技能调用本身不额外授权推送代码、邀请账号、扩大权限、发送材料或部署。

保留现有工作。需要推送时确认目标 remote、分支和待发布内容；权限变更使用已确认的接收身份和权限范围。外部操作完成后回读结果；响应不明确时先核实状态再决定是否重试。邀请已发出与已接受、提交已推送与本地文件已交接分别记录。

缺失信息只阻塞依赖它的操作，其余准备继续进行。确需用户决策时提出最关键的问题，并保留尚未完成项；不要用默认值掩盖阻塞，也不要将未授权的动作写成 Hermes 已获授权的任务。

## 5. 生成独立可用的接力提示词

先简述交接就绪程度及关键缺口，再给出一份可直接发送给 Hermes 的中文提示词。提示词应包含以下信息，可根据任务合并组织：

- **目标与完成标准**：最终结果、交付物、范围和验收条件。
- **必要背景与约束**：用户确认的决策、需遵循的项目说明，以及适用授权。接收方读不到的本地说明应提取必要内容，或先提供可访问副本。
- **材料与当前状态**：获取入口、版本、工作进度、关键验证结果，以及尚未交接的内容。
- **接手步骤**：先确认身份、材料版本和必要环境，再从明确的下一步继续；按依赖顺序安排工作，并说明遇到已知阻塞时如何处理。
- **验证与回报**：按验收标准检查，报告完成内容、实际验证结果、产物位置、剩余问题和需要用户处理的事项。

给 Hermes 足够的决策空间，不将来源中的猜测写成结论。具体命令只在已检查的接口和状态足以支持时提供，并写明必要执行位置或前提；对执行必需的未知值，要求先核实再执行依赖步骤。

要求 Hermes 接手时比对实际状态与交接快照：轻微变化可在授权范围内适配；影响目标、覆盖现有工作或改变操作影响的差异应先报告。发现已有任务仍在执行时先核实结果，避免重复提交或启动。

除非用户要求，不直接发送提示词或启动 Hermes。用户要求保存时创建交接文件并核实路径；要求发送时使用已确认的目标和渠道，并区分发送成功、接收确认和任务完成。

## 6. 交付前检查

完整阅读生成的提示词，确认：

- Hermes 无需当前对话即可理解目标、关键约束和下一步。
- 每项必要材料都有获取入口或明确的缺口说明；版本与状态一致。
- 已完成的判断有证据，未完成的工作有接手步骤或阻塞说明。
- 未继承其他项目的账号、地址、路径或部署假设，未扩大授权。
- 验收结果可观察，交付物位置明确或有确定位置的方法。

最终报告只将已核实事项标为完成。存在关键缺口时，明确说明交接仍需补充什么。
