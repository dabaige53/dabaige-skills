# 历史复盘与资产选择

用于跨任务的工作复盘、方向分析和长期资产建议。当前任务的单项需求检查不必展开完整历史调查。

## 证据与覆盖

用任务目录、会话索引和工作记录确定时间、项目与来源边界，随后读取原始对话及相关交付。记忆和摘要可帮助定位长期线索，重要判断回到用户原话与实际文件、提交、PR 或 Issue。对话证明用户说了什么，实际交付与验证记录证明执行到什么程度，两者分开核对。

跨工作区时，先确认项目身份及记录归属，按实际存储结构读取，不假定固定数据库字段。需要日历、文档或其他业务系统才能确认的内容，使用当前可用且获授权的来源。缺少来源时缩小结论，不以活动数量替代成果或影响。

用户要求全部读取时，逐项记录读取进度和缺失材料，汇总结论不能提前把范围标记为完成。重复副本只保留一次事件计数，保留原始出处方便追查。历史要求需结合后续修订判断当前是否有效。

## 分析工作模式

按实际工作内容聚合产品开发、数据分析、写作、研究、运营和上下文交接等工作，不强求覆盖所有类别。对每个有证据的问题核对：

- 用户希望获得的结果与实际投入、交付是否一致；方向偏移以用户明确目标为参照。
- 哪些操作和纠正独立出现多次，返工发生在哪个环节。
- 问题来自需求理解、信息缺失、工具限制、执行选择还是验收不足；证据不支持时保留多种可能。
- 哪些工作值得继续、减少、停止或在允许时委派；说明依据与代价，不自动实施。

只有出现至少两次独立事件，或有明确依据表明一次高成本工作将再次发生，才将其作为长期资产候选。单次明确偏好可以约束对应任务，不能直接推定为所有任务的全局规则。

## 选择最小可用资产

先查已有资产是否仍启用、由谁维护、能否通过小范围修改解决问题。推荐形式由重复工作的性质决定：

| 工作特点 | 可考虑的形式 |
|---|---|
| 需要上下文判断的可重复工作 | Skill |
| 简短且固定的输入或命令 | 模板、Snippet 或脚本 |
| 可被稳定事件触发、结果可确定判定 | Hook |
| 到指定时间或周期后检查、提醒 | Automation |
| 长期定义、约定与验收依据 | 参考文档或项目规格 |
| 当前资产已覆盖大部分需要 | 修改已有资产 |
| 一次性、输入输出不稳定或证据不足 | 暂不建立资产 |

每个值得实施的建议说明支持证据与日期、复现信号、置信度、现有资产重叠、预计收益与限制，并给出触发条件、输入、输出及可观察的验收方式。只保留影响选择的信息，不强制所有资产采用同一文档结构。

获授权创建或修改时，只提炼可复用的规则与资源，项目报告、原始对话和私人数据仍留在原处。效果需要后续真实任务验证；结构检查通过不等于返工已经减少。
