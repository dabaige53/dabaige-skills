# 维护项目验证 Skill

从用户指定的项目、应用和功能确定范围。按项目约定查找验证 Skill 的维护目录；普通 Codex 项目查看 `.agents/skills/verify-*/`。已有其他客户端的验证 Skill 时也可维护。遇到 Magpie 分配链接，定位源码后再编辑。没有对应 Skill 时，指出可以用 `$create-verification-skill` 创建。多个候选且无法判断时，列出候选让用户选。

1. **对照功能与入口。** 从 `features/README.md` 找到本次涉及的功能页，核对索引、实际路由、命令、界面和最近改动。新增遗漏项要能指出具体源码入口。仅当独立调查确有收益时，按项目约定并行阅读；操作同一应用实例由一个执行者负责。
2. **选定实跑范围。** 说明要走哪些用户入口、为什么。针对变更只跑受影响的功能和必要依赖；用户只要求审阅时，交付源码发现。要求全功能实跑或全量测试时，先核对当前任务是否已明确授权目标项目、范围和运行环境。逐项记录已运行、只读检查和未覆盖。
3. **从用户入口复查。** 按验证 Skill 的启动方式识别本次实例；第一次操作、每个独立会话和异常后都检查实例状态。健康检查无法识别界面卡住时，恢复已知状态再试。合并可共用的准备步骤，保留每个不同入口的实际结果。
4. **按原因处理。** 说明过时就改说明，脚本失效就改脚本并重跑受影响的操作。若应用行为本身有误，记录触发步骤、预期、实际结果和证据，产品修复按任务范围处理。某个入口不可达时，写出尝试过的路径和缺少的前提。
5. **清理与交付。** 清理此次运行及失败尝试留下的进程、会话和数据，保留并检查证据。交付查过的功能、修改位置、已验证结果和阻塞。只在用户要求时提交、推送、创建 PR 或安排定期维护。
