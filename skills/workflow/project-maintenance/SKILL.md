# 项目文档配置与维护

维护项目文档，并在 AGENTS.md 中提供阅读入口。先使用已有正文，缺少必要内容时再补充或新建。

## 1. 确定范围并盘点

先区分本次是只读检查、构建规范，还是整理现有体系。读取 README、AGENTS.md / CLAUDE.md、文件管理规则和目标文件的未提交改动，确认项目用途和允许修改的范围。

列出范围内的文档，逐份读完，记录路径、用途、是否有效、何时更新及哪些文件引用它。长文件分段读取。混合内容标明所在章节，不只看文件名或标题。分别统计规范、实现说明、方案、历史记录、导航和附件，每份文件只计一次。单列未读、截断或无法取得的材料。

核对相关代码、配置和验证证据，区分用户目标、当前实现和已验证结果。复盘整段会话时翻页至起点，读完批注和后续修正，以用户最后明确的决定为准。只询问无法查明且影响结果的关键问题。

盘点结束时，每份已读文件都有分类，未读材料和内容冲突已列明。

## 2. 确定地址与处理方案

整理体系时读取 [文档分层与迁移](references/document-lifecycle.md)，按 [文件用途与模板](references/project-files.md) 选择文档与默认地址。新建体系使用该地址表；已有项目沿用明确的文件管理约定。用户要求统一目录时，按确定的目标迁移。

按下表判断处理方式：

| 发现 | 动作 |
| --- | --- |
| 职责清楚、内容有效且完整 | 保留 |
| 职责正确但缺少已确认要求 | 原处补充 |
| 过时、矛盾或大量过程备注 | 核对证据后改写现行正文 |
| 多份文件维护同一要求 | 合并到负责该规则的文件，保留独有内容 |
| 一份文件混合规则、实现、计划和结果 | 按章节拆分到对应职责 |
| 内容正确但名称或位置不符 | 改名或移动并更新引用 |
| 缺少必要职责且没有可复用正文 | 新建 |
| 重复旧版或失效材料 | 核对独有证据与引用后，按授权清理 |

整理每份文件的当前路径、目标路径、处理动作和理由，说明原内容放到哪里、哪些入口需要更新。

首次写入文件前必须停下确认：按 [回复模板](references/response-templates.md) 的「需要确认」给出改动清单，等用户回复后再执行。只读检查不需要确认。用户明确要求直接执行，或逐批处理中已确认的批次，可以跳过。执行中出现清单外的改动，再确认一次。

执行前，每项改动都有目标地址，并已获用户确认。

## 3. 改写与整理

只读取选中的模板。每份文件回答一个明确的问题，写清适用条件、操作、结果和更新时机。删除不适用章节和模板提示。

- 每条要求只维护一处，定义、规则和例外放在一起。保留有效约束和独有信息，合并同义表达。
- 现行正文只写有效要求，保留仍有效的明确禁令。删除过时备注和撤回方案，将独有的历史事实与证据放入记录。
- 设计要求与实现状态分开，未实现方案标明状态；不能为消除文档冲突而把产品目标改成现有代码行为。
- 可直接从配置查询的版本、命令和字段优先指向源定义，文档保留用途、选择条件及不明显的约定。
- AGENTS.md 用链接导航；其他文档少用链接，仅在必要的定义、依赖或证据处使用，使读者能在本文中读懂相关要求。

在根目录 AGENTS.md 更新文档阅读区，每份相关文档一行，包含阅读条件、相对链接和用途。文档正文放在 docs/；目录总览按需维护在 docs/README.md。普通规范原位更新，Git 保存历史；ADR 按决定新增。

移动、合并或改名时同步导航、章节锚点、脚本、配置、生成器和检查规则的引用。适配 Skill 或插件优先改用已有正文及所需文件名；确需链接入口时保持单份正文，分别检查正文可用和工具能否自动发现。

整理结束时，正文和入口已保存，独有内容已保留，重复规则和旧路径引用已处理。

## 4. 检查与回复

用项目现有命令检查本次改动。核对内容是否符合事实、修改是否在授权范围内，检查模板提示、重复或冲突的规则、失效链接和章节锚点，以及迁移后遗漏的引用。确认未改动无关内容。失败时修正实际问题后重查，不因文档整理扩大到无关测试。

回复参考 ASD-STE100，以自然中文为准。先说结果，使用常用词、短句和具体动词，同一概念保持同一称呼。只写影响判断和下一步操作的信息。

按当前场景使用 [回复模板](references/response-templates.md)，只输出一种模板。替换占位内容，删除无内容的可选项。回复用简短文字表达，不使用表格。不复述执行过程，不把建议写成已完成。

完成标准是文件已保存、AGENTS.md 入口可达、当前规则一致且可用。

## 范围

单次 PRD、计划、报告和事项状态沿用项目既有流程。本 Skill 确定这些文件放在哪里，以及哪些已确认要求需要写入现行规范。仅构建文档时记录实际行为；用户要求修改运行配置、数据源或性能时，再按需读取 [开发配置](references/development-setup.md)、[数据源调整](references/data-sources.md)、[性能优化](references/performance.md)，按授权执行。
