# 性能优化

仅在用户明确要求优化时使用。先记录可复现的输入规模、运行条件、耗时或重复工作量，再处理影响用户流程最大的瓶颈。

| 有证据的问题 | 可选处理 | 需要保持 |
| --- | --- | --- |
| 重复读取相同数据 | 单次执行内复用查询 | 缓存键覆盖来源与条件，结束后释放 |
| 局部操作仍处理全部对象 | 将范围参数传到查询和输出层 | 所选结果与原结果一致 |
| 分组逐次查询 | 批量查询或复用连接 | 粒度、空值与业务规则 |
| 循环重复扫描、读文件或解析字段 | 预处理、索引或分批读取 | 顺序、去重、校验和异常行为 |
| 大量计算阻塞服务 | 使用现有异步能力并限制并发 | 数据兼容、写入顺序和失败恢复 |
| 缓存持续累积 | 设置容量与失效策略 | 在途操作、已有引用及来源版本正确 |
| 启动重复构建 | 复用有效产物并保留重建入口 | 源码变化后可以刷新 |

选择能解决已确认瓶颈的最小改动。仅在测得重绘或布局开销时针对该问题改动 UI。保留限流、退避、重试和断点恢复，不以无限并发或无依据取消等待提速。

验证时固定输入和运行条件，记录数据规模、冷暖缓存状态、变更前后耗时或操作次数，并比较业务结果。异步处理还要检查读取响应与并发写入。只运行覆盖实际回归风险的必要检查。

区分合成输入、真实数据和代码推断。缓存项减少不能证明内存下降；未实测收益标为待验证。完成条件是结果、顺序、异常及恢复行为保持一致，且目标指标有可检查的改善。验证结果在交付中报告，不自动生成单次优化报告。
