# 开发配置

用户要求实际修改环境、运行参数或执行入口时使用。仅配置文档时记录现行方式；已有文件、配置格式及运行方式优先。

## 选择文件

| 文件或入口 | 承担什么职责 | 如何配置 |
| --- | --- | --- |
| 项目说明入口 | 用途、准备条件、运行方式、配置与输出位置 | 沿用 README；新增详细说明默认放入 `docs/` |
| Agent 约定 | 项目特有约束和必要文档入口 | 保留现有约定；文档阅读入口按主流程维护 |
| 环境变量入口 | 将当前环境的参数传给运行进程 | 沿用现有注入、挂载或文件方式，不默认新建 `.env` |
| `.env.example` | 说明需要哪些变量和如何填写 | 只有项目采用该方式时添加；仅变量名与非敏感示例 |
| 配置文件 | 数据源映射、路径、运行参数和业务选项 | 沿用现有格式，不增加平行配置系统 |
| 执行入口 | 定位项目目录、加载配置、启动实际进程 | 优先沿用现有脚本或命令；新增入口需匹配项目技术栈 |

编写 Agent 约定按主流程“改写与整理”一节执行，不另设写作规则。

## 贯通配置与运行

确认并记录参数覆盖顺序、路径解析基准和生效方式。文档、预检查、业务程序应使用一致的配置来源；确认所需环境变量传到实际进程。

沿用有效构建产物，同时提供源码变化后的重建方式。入口支持从其他目录调用时，确认它能定位项目文件。

凭据遵循当前会话及项目的凭据管理要求，按项目和环境隔离。保留已有挂载，不覆盖环境文件；如项目采用本地 `.env`，确认其被版本控制忽略。检查只输出变量名和状态，不输出秘密值；示例值不能视为有效配置。

## 完成条件

文件内容与项目一致，配置能解析，实际入口读取正确配置，运行进程收到必要变量，缺失配置有明确提示。按变更范围运行一次必要检查；外部依赖或授权不足时说明未验证部分，不能以文件已存在作为完成依据。
