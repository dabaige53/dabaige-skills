# 多阶段计划

**交付一批可以开始做的任务。** 从用户目标和已有材料出发，无需先写 spec。

1. 找到最终要改变的行为，以及会影响拆分的关键选择。
2. 用 [to-tickets](../../to-tickets/SKILL.md) 拆出每项都能交付可观察结果的任务。逐项写清影响的文件或接口、依赖和完成条件。需要按 PR 拆分时，标出各自的目标分支、先后顺序、可独立开始的项，以及需要人工判断的项；不要求所有项目使用 PR。
3. 对照已有任务记录合并重复工作。需要登记任务时写入项目共用的平台，并返回实际入口。

**交付：** 先做哪几项、哪些可以并行、哪些被什么阻断。用户只要求拆分时，到此结束。
