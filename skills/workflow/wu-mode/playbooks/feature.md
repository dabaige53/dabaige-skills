# 功能开发

**负责交付用户能用的变化。** 先从一次具体操作定位改动，再决定工作怎样拆开。

1. 从用户入口追到现有实现，找出数据从哪里来、经过谁、结果在哪里被使用。说清同一次操作改前和改后分别是什么结果。
2. 拆分前回答四个问题：什么必须先完成？哪些部分可以独立交付？哪些地方会同时写同一状态？最小且安全的分工是什么？
3. 沿用现有设计完成最小可用的一段，再接上其余使用方。用户只要计划时改走[多阶段计划](multi-phase-plan.md)。
4. 从原入口观察结果。若改动涉及其他使用方，按 `blast-radius` 的方法判断影响。需要 PR 正文时再用 `pr`。

**交付：** 现在能做什么、从哪里使用，以及仍需要用户判断的取舍。
