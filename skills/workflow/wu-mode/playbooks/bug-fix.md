# 故障修复

**负责找到导致症状的原因。** 用触发原问题的操作判断修复是否生效。

1. 固定出错入口、触发条件和实际现象。系统、环境或工具故障使用 `$fixit`。先利用已有记录；需要复现时从同一入口复现。
2. 列出能解释现象的原因，优先找一条能排除最多可能性的证据。状态不明确时，优先利用已有采样；需要时临时加观测点。证据推翻某个假设，应撤回仅由它支持的本轮修改。
3. 用户要求 TDD，或有便宜且明确的回归入口时，用 `$tdd` 先记录失败，再修复。
4. 检查修复效果时回到原入口。局部用例通过但原环境不可达，就分别说明这两个结果；无法确认原因时，把它写成假设。

**交付：** 什么坏了、原因是什么、改了哪里、原症状是否消失。
