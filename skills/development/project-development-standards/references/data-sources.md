# 数据源调整规则

## 确认业务来源

逐项记录：业务用途、原文件或数据库对象、目标对象、加工入口、字段与粒度、消费模块。优先检查现有连接适配器、正式元数据、迁移记录和原始实现。

历史航空项目约定为：`ho.duckdb` 保留，已确认迁移的 DDS、OAG 等业务库改读 PostgreSQL。将此作为这些项目的已知背景，在当前项目核实；不要扩展成所有项目、所有本地存储都必须迁移的通用规则。本地任务状态 SQLite、附件、模板、基础维表等按各自用途保留。

未迁移或没有明确对应关系的数据继续按文件管理。缺失时写入该项目 `error.md`，明确哪些功能受影响。已有明确目标的 PostgreSQL 读取失败时报告错误，不静默退回旧文件或返回空数据假装成功。不要自行新增表或用相似数据替代业务来源。

## 沿加工过程寻找派生数据

找不到旧汇总表名时，搜索消费函数、指标字段、SQL 聚合与原任务代码。旧表可能已由一次源查询生成多组结果，未必存在同名 PostgreSQL 表。

例如，历史 KPI 项目中的 OAG 月度市场供给和航司供给由 `publish.oag_cr` 按月、物理航节和航司加工产生。迁入功能时逐项检查加工模块、导入路径、SQL、依赖及参考文件，避免只复制界面或主脚本。

## 保持统计口径

核对日期边界、数据粒度、去重键、连接基数、空值、文本数值转换、单位与排序。特别检查正负交易记录、冲销、跨月与跨年、空结果及重复记录。保留既有班次、座位、份额、Top3、HHI 等指标定义。

优先下推过滤和必要聚合，减少传输量；变更前后对照行数、关键汇总与边界样本。共享连接或缓存前核实线程安全、事务边界及来源版本。目标映射正确不等于加工结果等价。
