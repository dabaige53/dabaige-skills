# 性能优化与验收

先按用户操作找到重复工作，再选择与问题对应的处理方式。

| 观察到的问题 | 优先处理 | 必须保持的行为 |
| --- | --- | --- |
| 多月份反复读取同一航线历史数据 | 一次任务内复用查询 | 缓存键覆盖来源、航线、条件；任务结束释放 |
| 单航点操作仍生成全部航点 | 将范围参数传到导出与查询层 | 所选输出内容与原结果一致 |
| 月份或分组逐次查询 | 合并查询、批量取数或复用连接 | 粒度、正负记录和空值规则不变 |
| 循环内反复构建索引、扫描列表或读文件 | 一次预处理、索引查找、分批读取 | 顺序、去重及异常行为不变 |
| Excel 逐行重复解析字段 | 预先计算字段位置 | 数值、月份、文件完整性校验保留 |
| 密码散列或大量计算阻塞页面服务 | 采用现有异步能力并限制并发 | 密码兼容、写入串行化和失败恢复 |
| 页面范围缓存无限累积 | 有界缓存与失效策略 | 在途任务、已有引用、来源版本正确 |
| 常规启动重复构建 | 复用有效产物并提供重建入口 | 代码变化后可刷新，不长期使用旧产物 |

缓存数量下降只能证明保留项减少；未测堆大小时不报告内存下降比例。异步导入应同时检查读取响应和并发写入，避免仅以总耗时判断成功。只有测得页面重绘或布局开销时才针对该瓶颈改动 UI。

保留下载限流、退避、重试和断点恢复。没有上游限制依据时不通过取消等待或无限并发提速。

验证时固定输入与运行条件，记录数据规模、冷暖缓存状态、修改前后耗时或操作次数，并比较输出。将合成测试、真实数据测试及代码推断分开。优先增加覆盖实际回归风险的检查，不为微小可逆调整编写重复实现的测试。
