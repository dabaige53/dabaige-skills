# workspace-cleanup

清理不再需要的文件和目录。代码、测试、规则和文档内部的内容删减属于内容清理。

## 清理范围

| 类型 | 删除前确认 |
| --- | --- |
| 临时文件与缓存 | 没有任务或进程使用，可以重建或已无用途 |
| 旧构建与运行结果 | 符合保留要求，未被发布、下载、回退或后续任务使用 |
| 日志与备份 | 超出项目保留时间或数量，未被故障调查或恢复工作依赖 |
| 废弃工作目录与 worktree | 任务已结束，无未提交、未跟踪或尚未保存到其他位置的独有内容，无 Agent 或进程使用 |
| 多端重复副本 | 共享位置已有完整、可读的内容，该本地副本不再被依赖 |

## 执行

1. 按用户指定的项目、目录和机器确定范围，读取已有清理与保留规则，找出占空间或任务遗留的内容。
2. 根据用途、引用、运行状态和保留要求决定是否删除。名称相似、修改时间旧或文件较大只能作为查找线索。
3. 在当前授权内，能确定的直接清理；不能判断的保留，继续处理其他项。工具管理的缓存、构建和 worktree 优先使用对应工具的清理方式。
4. 多端分别处理。删除共享文件前确认所有相关使用方；清理本地副本不连带删除共享文件。配置中的路径若指向范围外，先保留并列入待确认项。

已有内容由 Agent 自行查明。保留规则缺失、独有内容归属不明或使用情况无法确认时，最后集中列出，不逐项打断用户。

## 回复

简述清理了哪些位置和内容；有实际统计时再说明释放空间。未访问的机器写明未处理。

只有存在待确认项时列清单：

- **路径：** 保留原因；需要用户决定什么；建议如何处理。

只处理整个文件或目录。业务数据缺少保留期限时，交给用户决定。
