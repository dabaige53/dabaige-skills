# 配置优化

| 问题 | 处理方法 |
| --- | --- |
| 新节点需要执行项目任务 | 按项目兼容要求准备依赖、运行身份和工作目录，接入共享资源后启用对应入口 |
| 终端能运行，服务或定时任务失败 | 对照实际运行身份、工作目录、程序路径及配置加载方式 |
| 每次启动重复安装或构建 | 复用有效环境和构建，保留代码或依赖变化后的更新入口 |
| 各端数据或状态不一致 | 核对实际连接的实例、业务范围和存储，修正旧地址或独立副本 |
| 任务重叠、积压或争用 | 根据执行记录调整周期、执行位置和并发，保留必要批次 |
| 超时或重试过多 | 按真实延迟、错误类型和上游限制调整超时、退避与并发 |
| 缓存或临时文件耗尽资源 | 调整目录、额度和失效策略，保留在途任务需要的文件 |
| 结果需要人工搬运 | 接好现有上传、发布和访问入口，让下游直接读取对应产物 |

修改共享运行配置前保留相关旧值及恢复方式。优化前后使用相近输入和运行条件比较耗时、等待或失败次数，保持业务结果和恢复能力。
