# 旧项目迁移与重点检查

按子项目使用清单，状态标为待处理、已配置、已验证、受阻或不适用。记录配置位置和实际结果；未执行的检查保留待处理。

## 迁移安排

- [ ] 列出子项目、现有运行节点、启动与调度入口、依赖、数据、任务状态及产物位置。
- [ ] 确定各项的目标节点和共同来源，记录保留、调整、迁移或停用；标出必须本地运行及逐端配置的例外。
- [ ] 记录旧配置和恢复方式；涉及数据或状态搬迁时，确认迁移范围、备份及迁移期间新增写入如何处理。
- [ ] 按依赖顺序分批准备目标环境，调整配置、路径、连接、权限和输出入口。
- [ ] 比较迁移前后的业务结果、任务进度及产物可用性，再按授权切换入口和调度。
- [ ] 切换时处理旧任务与在途写入，避免新旧两端重复执行或覆盖结果。回退同时考虑配置和新增数据。
- [ ] 确认目标可用后，按授权停用旧入口；旧数据和文件的删除另按保留要求处理。
- [ ] 更新项目运行说明，留下各子项目的本地要求、使用入口和未完成项。

## 必须重点检查

| 重点 | 检查内容 |
| --- | --- |
| **本地依赖** | 桌面应用、硬件、浏览器登录态、本地服务或文件是否必须留在某台机器；区分真实限制和仅仅尚未迁移 |
| **逐端配置** | 每个执行节点是否需要独立准备依赖、凭据、权限、网络、挂载或服务配置；配置是否被实际进程读取 |
| **路径与地址** | 硬编码主目录、盘符、`localhost`、端口及相对路径，在目标节点实际指向哪里 |
| **共享来源** | 数据、任务状态和产物是否指向同一项目及业务范围，是否仍在使用独立副本或旧地址 |
| **运行版本** | 代码、构建、依赖和配置是否匹配，实际进程是否已加载本次修改 |
| **重复执行** | 旧计划任务、自启动服务和队列消费者是否仍在工作，切换时在途任务如何接续 |
| **产物交付** | 输出是否完整，后续节点能否读取，上传或发布是否完成 |
| **恢复能力** | 新配置失败时如何恢复，迁移后的新增数据和任务进度如何保留 |

从实际执行身份和节点检查。只看配置文件，状态记为已配置；实际运行和结果检查通过后再记为已验证。

## 本地要求的标记

每个子项目分别记录，可同时存在两类要求：

- **必须本地运行**：具体组件、指定机器、原因，以及其他节点如何调用或读取结果。
- **必须逐端配置**：哪些节点需要哪些依赖、变量、权限或挂载，配置位置和生效方式。

没有要求时写“无”；尚未查明时写“待确认”及缺口。记录凭据来源或变量名，不记录秘密值。
