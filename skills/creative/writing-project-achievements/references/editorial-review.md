# 文字审校与修改应用

## 明确交付范围

用户要求审查、给出建议或“一个新的diff”时，只新增指定审校文档，保持源稿、图片与汇总版本不变。用户已要求修改、重写，或明确采用建议时，按已授权范围应用，无需重复索取确认。不要将建议已生成表述为修改已落地。

以当前文件为审校基准；已有认可的方案、段落和业务细节继续保留。全文阅读后逐篇给出“保留、补充、重写”或具体局部调整结论，允许部分文章无需修改。把修改集中到确实影响阅读的表达，不为凑数量改遍每一篇。

## 审校顺序

1. **事实信息。**逐项识别交付物、指标、表目、分析对象、比较条件、用途及完成程度。保持全部有效信息，尤其保留数值、比例、阈值、例外条件和已有查询输出能力。
2. **段落衔接。**合并相邻段落的同义复述，将分散短句组织成连贯业务说明。表格或列表已逐项展开后，删去单纯再次罗列名称的句子，同时保留新增解释。例如10张图已逐项说明，后文不必重复10个名称，但独有的散点图解释应保留。
3. **结构对应。**核对“四类”等引导语与实际列表数量，统一同一层级的分类标准。将对象范围与指标类别分别说明，避免把覆盖机场放入天气指标分组。
4. **术语指向。**在适合读者的首次出现处解释缩写，确保单篇独立阅读与汇编阅读均无歧义；明确“国内”“当地”“同期”等词的参照对象。
6. **边界保全。**复查计划供给与实际执行、销售与承运、客票销售额与财务收入、资产盘点与本期新建、设计与交付等区别。文字顺畅不能以丢失这些信息为代价。

修改后信息可以更集中，不能更少。允许为理解服务的必要解释；不以更短、更华丽或更多修改衡量效果。不新增未经来源证明的功能、结论或成效。

## 输出审校diff

用户要求可审阅差异时，默认在一份文档中包含：简要审校结论、逐篇处理表、每处修改的定位与理由、原文和建议改文。使用标准diff代码块，删除行标记“-”、新增行标记“+”，保持真实换行。标题明确这是建议还是已应用。


范围只含文字审校时，以现有正文的事实范围为边界；需要补事实时另读来源并明确处理范围。保留例子中的独飞100%条件、行业运力查询等实质信息，不能因它们使句子变长就省略。

## 应用已采用的修改

逐处检查当前原文是否仍与建议稿一致。发生漂移时重新核对该段，避免盲目替换和覆盖后续编辑。应用后逐项核对新段落、数值与条件，确保没有漏项、重复替换或不相关改动。

同步本次授权涉及的单篇和汇总版本，保留图片。用户仅指定文字文件时，不恢复已删除的其他交付格式。更新diff文档的应用状态，按实际修改统计项目数与处数；未改篇目继续保持原文。

最终检查源稿与汇总内容一致、所有已采用建议已落实、建议阶段未获授权的文件保持不变。实际无法完成的同步或检查，在交付说明中明确范围。
