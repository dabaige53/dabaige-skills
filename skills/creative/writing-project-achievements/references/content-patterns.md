# 内容展开标准

## 按交付类型展开

| 成果类型 | 展开内容 |
|---|---|
| 看板与页面 | 逐页说明分析对象、指标、维度、同比环比或预算实际等比较关系、筛选下钻能力及经营用途。 |
| 专题分析报告 | 逐章说明研究问题、分析对象、时间和市场范围；逐表说明字段、分组、排序、比较方法和业务用途。实际结论有依据时写入。 |
| 预测与测算工具 | 写清预测对象、应用场景、输入参数、业务计算逻辑、结果指标、方案比较与审核、输出内容。 |
| 数据采集与自动化 | 写清数据对象、覆盖范围、字段内容、加工结果、更新周期、交付载体及下游业务；将历史补采与持续刷新分别说明。 |
| 指标与语义治理 | 写清统一的业务对象、指标含义、计算范围、使用规则和可用字典或标准，以及服务的分析场景。 |
| 通用分析工具 | 写清用户可完成的分析任务、输入与输出、交付功能和适用范围，区分系统自动处理与业务判断。 |
| 研究与规划方案 | 写清研究问题、范围、方案、规则、建议和后续用途，保持研究或方案的完成程度。 |
| 资产梳理与业务分享 | 展开具体业务主题、解释的指标和方法、整理出的可用资产及使用场景；资产盘点不能全部计作新建。 |
| 运行维护 | 写清得到维护的业务交付、覆盖对象、更新内容和持续使用能力；只掌握维护证据时，不杜撰专题分析内容。 |

## 报告展开示例

“形成四章、11张表”只说明规模。继续列明每章研究什么、各表比较什么、字段如何服务经营判断。多张表同构时先解释共同指标，再逐表说明分组、筛选和用途。不要固定套用四章、11张表，采用实际报告结构。

下面示例仅演示表达粒度，不是可直接移用的项目事实：

**交付授权代理销售分析表，形成代理贡献、销售变化和渠道开发对象的分层分析。**按代理列示名称、IATA代码、渠道性质、全航司净销量、本航司净销量、其他航司净销量、本航司销售额、销售占比及同比、环比变化，支持按代理、国家、城市和销售状态筛选。

分析覆盖重点贡献代理、销量增长与下滑代理、本航司销售占比较低的代理，以及有其他航司销售但无本航司销售的授权代理。结合销售规模、占比和变化趋势，为营业部确定渠道维护、销售跟进和代理激活的重点对象提供依据。

## 措辞调整

| 原表达的问题 | 调整方向 |
|---|---|
| “修正筛选口径和汇总问题”只讲开发动作 | 依据真实功能写“形成按代理、地域及授权范围比较销售表现的分析能力”，再展开指标和用途。 |
| “整理HTML报告、说明文档及项目清单”只讲包装 | 写报告研究的市场、供需关系、客流、价格或经营表现，按实际章节展开。 |
| “配套文字分析进一步识别”像写作说明 | 直接写“形成代理分层分析，覆盖重点贡献、销量变化与渠道开发对象”。 |
| “显著提升效率、全面赋能”没有内容或依据 | 写具体可用交付和业务用途；有实际成效证据时再写量化结果。 |

保留对业务规模有意义的市场、部门、周期和对象范围。内部文件数、接口数、任务数通常不能帮助领导理解成果。术语首次出现时按读者需要简要解释。
