# 检查与迁移

1. 检查当前项目及未提交改动；跨项目沿用用户指定范围。默认排除 CodeX-Settings、Codex 配置和网站登录项。运行 `scripts/audit_secrets.py <项目绝对路径>`，另核对隐藏配置及实际消费者；跳过 FIFO，零匹配不证明没有凭据。
2. 区分待迁移、已管理、占位值、应用会话和历史副本。分别统计配置位置、不同凭据和拟建条目，标明项目及环境；未知环境不推断。
3. 已授权迁移则继续；仅发现问题时先给可审阅方案。按服务、账号和环境复用已有条目，值相同仅是合并线索。使用当前 Service Account 可访问的项目保险库，不自动扩权。
4. 短名称采用“服务 + 用途”，新条目最多一个“项目凭据”标签；项目、来源和环境放描述。保留现有无关内容。OAuth 会话和缓存由原应用管理，私钥及加密密钥保持原值与格式。
5. 在本机进程内读取原值，用 JSON 标准输入写入并回读比较；只输出元数据。保存稳定条目及字段 ID 到仓库外 `projects.json`，复用共享凭据映射。未知写入结果先回读再重试。
6. 先确认值一致，再清理旧引用或明文。逐个检查旧消费者，必要时保留已确认的本机配置回退；保留用户其他改动，不另建明文备份。
7. 通过实际入口验证变量解析及加载优先级，再按授权做最小功能检查。失败只回退本次修改；未测数据库或部署时明确说明。历史或日志泄露、密码轮换及生产变更单独处理。

完成条件：每个候选有结果，已保存值一致，原运行入口获得所需变量，失败和未验证项明确；仓库无工具依赖和相关文案。无候选不建空条目，不创建后台扫描。
